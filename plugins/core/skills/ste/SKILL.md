# Simplified Technical English

Apply ASD-STE100 Issue 9 to the English prose in the requested task.
Use the skill when the user requests STE or active instructions require it.
An unrelated request does not select STE unless those instructions also apply to it.
Accept input in any language or style.

## Write or review

1. Identify the reader, purpose, required format and prose that the task permits you to change
2. Read [the local rules](references/rules.md) before writing or reviewing the prose
3. Read [the examples](references/examples.md) when a rewrite needs a pattern for instructions, uncertainty or protected text
4. Write or revise the prose, then review it against the rules and the original meaning
5. Return the requested result and identify a material verification limit when it affects that result

Preserve facts, uncertainty, requirement strength, commitments, numbers and technical meaning.
Keep conditions, exceptions and time references precise.
Keep exact quotes, code, commands, paths, URLs, identifiers and required template text unchanged.
Apply STE to the prose around those elements.
Keep machine-readable contracts valid.
Do not rewrite source evidence or past documents unless the task requires it.

If a source statement has more than one possible meaning, do not select a meaning without evidence.
Use the available context to resolve it or ask the smallest necessary question.
For a review-only request, return findings and leave the source unchanged.

## Keep the required format

Follow required repository formats, technical contracts and safety rules.
Use STE before optional style advice from another writing skill.
Keep personal number formats and Markdown source layout in the user's instructions.
Do not change them into additional STE rules.

## Review limits

The local rules and examples are a concise guide, not the full standard or dictionary.
Use an available authoritative reference supplied by the user for an uncertain rule or vocabulary choice.
When no such reference is available, use the local guidance without claiming a complete vocabulary review.
Do not invent an approved meaning or call an ordinary word a technical term to avoid a rewrite.
Preserve a necessary technical term if its approval is not established.
Identify its approval as unverified in a compliance assessment.

If strict simplification loses meaning, retain the precise wording and identify the material departure or unverified point.
Before returning or saving prose, review its meaning, structure, vocabulary choices and protected text.
Do not claim full STE compliance without a complete review of the applicable rules and vocabulary.
When the user requests an assessment, state what the review covered and what remains unverified.
Do not add a compliance notice to every ordinary reply or draft.
